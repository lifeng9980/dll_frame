# IR SDK 客户接入与配方指南

## 1. 包内目录与运行入口

| 目录 | 内容 |
|---|---|
| `include/` | 稳定的纯 C ABI 头文件（`IR_status.h`、`IR_types.h`、`IR_station.h`、`IR_device.h`、`IR_recipe.h`、`IR_analysis.h`、`IR_plugin_abi.h`、`IR_plugin_cxx.hpp`） |
| `windows-x64/bin/` · `lib/` | `IR_station.dll`、`IR_analysis.dll`、`ir_run_recipe.exe`、`ir_capture_accept.exe` 与 MSVC 导入库（双平台包另含 `linux-x86_64/`） |
| `examples/` | C、C++、C#（`.NET 10`）与 Python（`ctypes`）示例，以及 `stations/` 工位模板和 `recipes/` 配方模板 |
| `simulators/` | 单设备模拟器 `ir_sim_devices.py` 与组合式虚拟工位 `ir_virtual_station.py` |
| `docs/` | 本说明（整体架构、支持边界与第三方组件说明见根目录 [SDK.md](../SDK.md)） |

### 第一次离线运行与常见样例

在 SDK 解压目录用包内工位与配方 JSON 执行离线预检。

```powershell
& '.\windows-x64\bin\ir_run_recipe.exe' --check --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json'
```

运行配方需要自备 RAW 数据。`noise_roi.json` 至少需要两帧、画幅至少为 `160×128`。创建 `out` 目录，将工位模板复制进去，并把副本的 `acquisition.source` 改为含 `frames.raw` 和 `frames.csv` 的数据目录。

```powershell
New-Item -ItemType Directory -Force .\out | Out-Null
Copy-Item .\examples\stations\offline.json .\out\station.json
# 编辑 .\out\station.json 后运行
& '.\windows-x64\bin\ir_run_recipe.exe' --run --station '.\out\station.json' --recipe '.\examples\recipes\noise_roi.json' --output '.\out\offline-run'
```

- `stations/offline.json` + `recipes/noise_roi.json`：运行 `temporal_noise`、`roi_mean`、`save_raw` 与限值判定。
- `stations/offline.json` + `recipes/nodisk_roi.json`：无存盘多指标示例（`raw_saved=false`，`frame_stats -> map_summary -> roi_mean`）。
- `stations/sim_tcp.json` + `recipes/noise_blackbody.json`：TCP 黑体设温等稳后采集（配合 `python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010`）。
- `stations/sim_power_serial.json` + `recipes/power_serial_output_cycle.json`：IT6332A 串口设定、打开输出、取帧后自动下电并回读确认。
- `stations/sim_virtual_station_tcp.json` + `recipes/virtual_station_hil.json`：配合 `python .\simulators\ir_virtual_station.py --mode tcp` 和自备 RAW，验证虚拟仪器联动与 `fft2d`。

### 自定义算子插件和指定相机采集

`examples/plugins/mean_dn.cpp` 展示纯 C ABI 插件入口、准备期输入声明、U16/U32 帧视图读取和标量输出。用客户包中的 `examples/CMakeLists.txt` 构建：

```powershell
cmake -S .\examples -B .\build-example -G Ninja -DCMAKE_BUILD_TYPE=Release -DIR_SDK_ROOT="<已解压的 SDK 目录>"
cmake --build .\build-example --target ir_example_mean_plugin
```

将 `examples/stations/offline.json` 复制为本地工位配置，将 `acquisition.source` 指向 RAW16 回放目录，并加入插件库路径；插件路径可使用绝对路径，也可按工位 JSON 所在目录填写相对路径。用 `examples/recipes/plugin_mean_dn.json` 执行 CLI `--check` 和 `--run`。示例插件输出输入批次所有像元、所有帧的平均 DN；配方中的 `3.5 DN` 限值对应 0 到 7 的小型示例数据，实际 RAW 数据应按预期值调整限值。

用随包提供的采集 CLI 选择已枚举相机的 `device_path`，再采集并保存 JSON 报告：

```powershell
$camera = (& .\windows-x64\bin\ir_capture_accept.exe --list | ConvertFrom-Json).capture_devices | Where-Object name -eq 'FX3' | Select-Object -First 1
& .\windows-x64\bin\ir_capture_accept.exe --backend directshow --source $camera.device_path --frames 64 --cycles 8 --preview-ms 2 --report .\fx3-capture.json
```

若枚举到多台 FX3，请从列表中选择所需设备对应的完整 `device_path`，再传给 `--source`。

使用 `--emit-station-json` 生成工位配置时，同时传入 `--raw-source` 指定 RAW 回放目录。

## 2. 工位文件与 `schemav` 配方格式

- CLI、C# 和 Python 示例从当前工作目录解析相对输出路径。运行前先创建父目录，本次运行独占创建输出目录。工位中的离线 `acquisition.source` 与 `plugins` 路径相对工位 JSON。
- **工位关键字段**：`schemav`（默认 `1`）、`acquisition`（`backend`、`source`、`valid_bits`、`queue_capacity` 默认 64、`max_batch_bytes` 默认 256 MiB、`max_inflight_bytes` 默认 1 GiB）、`devices`（设备别名映射）与可选 `plugins`。
- **预检与插件**。调用 `IR_CheckRecipeJson` 或 CLI 的 `--check` 时，SDK 不打开采集源或仪器，也不创建配方运行结果。若工位配置了 `plugins`，预检会加载配置中的库，调用插件的 `ir_plugin_query`，并对配方引用的插件算子调用 `prepare`。插件及其辅助库使用进程级缓存，更新后须重启宿主进程。
- **槽位与预算**：同一步骤的输出槽须互不相同，且与输入槽分开。不同步骤可重用同名同类型的输出槽。`max_inflight_bytes` 计入 SDK 管理的采集缓冲、批次像素和帧戳、在用指标槽及临时输出。`save_raw` 引用已采集批次，同名槽重采时计入仍待归档的旧批次。数学库工作区和插件私有内存由各自管理。
- **常用步骤类型**：
  - 仪器控制：`blackbody`、`power`（开启输出时必须设 `off_after_run: true`）、`power_wait_stable`、`oven_stabilize`、`oven_standby`、`dmm_read`、`detector_timing`、`detector_gpol`、`detector_register`、`detector_current`、`cooler_read`。
  - 采集与分析：`flush_frames`、`capture`、`analyze`（16 项内置算子或 `plugin:<ns>.<name>`）、`save_raw`（可选 `subdir`）、`repeat_burst`（周期无存盘流式追加 CSV）。
  - 安全收尾：`safety.blackbody_standby` 与 `safety.oven_standby` 在正常结束、失败或取消时自动恢复待机状态。

### 图像数组输入

分析库的原始帧算法通过 `IRArrayView` 描述调用方持有的紧密数组：`data_type` 是内存元素类型，`byte_size` 是缓冲区字节数，形状为 `[frames][height][width]`。帧统计、ROI 均值、NUC 帧统计、Noise3D、通道频谱和闪元检测接受 U16 或 U32，不会先把整批输入转换成另一种类型。离线 RAW 回放支持 RAW16 与 RAW32_LE；当前 DirectShow / V4L2 实时采集仍输出 U16。RAW32 算法输入能力不代表已支持某种硬件 RAW20 传输编码。当前 GB/GJB 配方指标基于现有物理测量模型，原始数据 `valid_bits > 16` 或 U32 位宽未知时会被预检拒绝；`valid_bits` 不会自动换算成 `digital_full`、ADC 满量程或探测器饱和点。

```c
IRArrayView input = {pixels, pixel_bytes, IR_TYPE_U32, width, height, frame_count};
IR_FrameStatistics(&input, 1, mean_map, std_map, pixel_capacity,
                   summary, 2, error, sizeof error);
```

### 退出码、结果目录与诊断定位

| 状态 | CLI 退出码 | `result.json` `run_status` | 说明 |
|---|---:|---|---|
| 测量通过 | `0` | `PASS` | 全部步骤完成且满足 `limits` |
| 超出限值 | `20` | `NG` | C ABI 返回 `IR_OK`，测量完整但未满足 `limits` |
| 执行失败 | 非 `0`（对应 `IRStatus`） | `ERROR` | 本次运行可独占并写入目录时生成诊断 `result.json`，`IR_BUSY` 仅返回状态 |
| 外部取消 | `8` | `CANCELLED` | 收到 `IR_RequestStop` / `CTRL_BREAK_EVENT` 并执行安全收尾 |

`result.json` 包含 `error_status`、`failed_stage_name`、`failed_step_index`、`cleanup_status`、`step_records`（逐步耗时）、`total_duration_ms`、`limits_summary` 与版本溯源字段；`frames.csv` 附带 `timestamp_ms,time_origin,delta_ms`；`burst_summary.csv` 附带 `elapsed_s`（3 位小数）与明确单位列名。

### DMM6500 与 IT6332A USB-VISA 连接

Windows x64 安装 NI-VISA 运行时后，可从 NI MAX 复制 USB INSTR 资源名。将 `{"visa_resource":"USB0::0x05E6::0x6500::<仪器序列号>::INSTR","timeout_ms":2000}` 传给 `IR_OpenDevice(IR_DMM6500, ...)`，或将 `{"visa_resource":"USB0::0x2EC7::0x6332::<仪器序列号>::INSTR","timeout_ms":1200}` 传给 `IR_OpenDevice(IR_IT6332A, ...)`，也可写入工位的 `devices.<别名>.connection`。DMM6500 仪表应处于 SCPI 命令集。每次连接从 `visa_resource`、`host` 和 `port` 中互斥选择一种；同一 `visa_resource` 不可被重复打开（返回 `IR_BUSY`）。SDK 仅在打开 VISA 连接时加载系统的 64 位 `visa64.dll`。TCP 和串口连接仍只需要 SDK 双库。其中 DMM6500 USB-VISA 已真机验证，IT6332A USB-VISA 已实现并完成离线校验，待实机联调验收。

### 独立仪器等待

`IR_WaitBlackbodyStable`、`IR_WaitOvenStable` 和 `IR_WaitPowerCurrentStable` 与配方执行、已启动的采集共用进程级取消状态。另一线程持有其中一项活动操作时，独立等待会返回 `IR_BUSY`，即使使用不同的设备句柄。将这些调用安排在同一工位工作线程，控制线程可用 `IR_RequestStop` 请求取消当前活动操作。

## 3. 多语言调用示例

### C / C++ 独立工程（`examples/CMakeLists.txt`）

```powershell
cmake -S .\examples -B .\build-client -G Ninja -DCMAKE_BUILD_TYPE=Release -DIR_SDK_ROOT="$PWD"
cmake --build .\build-client
```

C ABI 核心入口：`IR_CheckRecipeJson` 与 `IR_RunRecipeJson(station_json, recipe_json, output_directory, options, &run, error, sizeof error)`（`options` 可传 `NULL` 或挂载 `IRRecipeStepCallback` 实时接收步骤事件）。`ir_analysis_c_sample`（`examples/analysis_algorithms.c`）仅链接 `IR_analysis`；`ir_capture_accept` 支持 `--list` 枚举设备与多轮采帧拷机。

### C#（.NET 10 P/Invoke）

```powershell
$env:IR_SDK_LIB_DIR = (Resolve-Path '.\windows-x64\bin').Path
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- --recipe .\out\station.json .\examples\recipes\noise_roi.json .\out\csharp-run
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- --analysis
```

Linux（Ubuntu 24.04）下若未将 `.so` 安装到系统库路径，可通过 `export IR_SDK_LIB_DIR="$PWD/linux-x86_64/lib"` 指定动态库目录（解包后默认也会自动探测 `linux-x86_64/lib`）。

### Python（标准库 `ctypes`）

```powershell
python .\examples\python\ir_recipe.py --check .\examples\stations\offline.json .\examples\recipes\noise_roi.json
python .\examples\python\ir_recipe.py --run .\out\station.json .\examples\recipes\noise_roi.json .\out\python-run
python .\examples\python\ir_analysis.py
python .\examples\python\ir_drift_nodisk.py --mode self-test
```

自测默认在系统临时目录创建唯一输出目录。实测和回放可通过 `--output-dir` 指定新目录；若目录已存在，程序会在连接设备前退出，以保留已有结果。
