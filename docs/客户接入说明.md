# IR SDK 客户接入说明

## 包内目录

| 目录 | 内容 |
|---|---|
| `include/` | 稳定的 C 接口头文件 |
| `windows-x64/bin/` | `IR_station.dll`、`IR_analysis.dll`、配方命令行 `ir_run_recipe.exe` 与通用采帧验收工具 `ir_capture_accept.exe` |
| `windows-x64/lib/` | MSVC 导入库，供客户编译 C/C++ 程序 |
| `linux-x86_64/lib/` | `libIR_station.so` 和 `libIR_analysis.so`（双平台包提供） |
| `linux-x86_64/bin/` | Linux 配方命令行 `ir_run_recipe` 与采帧验收工具 `ir_capture_accept`（双平台包提供） |
| `examples/stations/`、`examples/recipes/`、`examples/data/` | 工位模板、配方（v1 与 v2 无存盘样例）和离线 RAW16 样例 |
| `examples/schemas/` | 工位与配方（v1 / v2）的 JSON Schema（Draft 2020-12），供编辑器补全与校验 |
| `examples/` | C、C++、C# 和 Python 调用样例 |
| `docs/` | 本说明、测试人员配方指南、设备支持矩阵和第三方组件说明 |

应用随目标平台部署两个 SDK 库（若仅调用独立算法算子，只需 `IR_analysis`）。Station 会加载同目录的 Analysis。包中没有 Qt、Asio、FFTW 或 JSON 运行库。两个库分别导出 `IR_StationVersion()` 与 `IR_AnalysisVersion()` 以便核对版本，Windows DLL 同时带有 `VERSIONINFO` 文件版本资源。Windows 客户机需要安装相应的 MSVC x64 Runtime；Linux 预编译包需要系统 C/C++ 运行库（GLIBC 2.38+）。单平台 Windows 交付包仅包含 `windows-x64/`，双平台交付包同时包含 `windows-x64/` 与 `linux-x86_64/`。

## 第一次离线运行

工位连接与测试步骤分成两份 JSON。在解压后的包根目录先做只读预检，再运行随包离线样例。Linux 使用能保留执行权限的工具解包，例如 `unzip` 或 `cmake -E tar xf`。

```powershell
& '.\windows-x64\bin\ir_run_recipe.exe' --check --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\offline-run'
& '.\windows-x64\bin\ir_run_recipe.exe' --run --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\offline-run'
```

```bash
./linux-x86_64/bin/ir_run_recipe --check --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/offline-run
./linux-x86_64/bin/ir_run_recipe --run --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/offline-run
```

首跑输入为两帧 `1×1` RAW16。全图和 ROI 均值都是 `21 DN`，时域噪声约 `1.4142135623730951 DN`，判定为 `PASS`。练习 ROI 时换用 `examples/stations/roi_2x2.json` 与 `examples/recipes/noise_roi_2x2.json`，新输出目录中的全图均值应为 `51 DN`，左列为 `41 DN`。结果目录包含 `frames.raw`、`frames.csv`、`result.json`，每次使用一个尚不存在的新目录。

RAW 源路径与 `plugins` 路径相对工位 JSON；输出路径相对流程 JSON。SDK C ABI 接收 UTF-8 JSON 字符串，C# 和 Python 不需要 JSON 原生库依赖。

## 工位文件与测试流程

工位文件维护采集源及设备连接，例如 `examples/stations/sim_tcp.json` 与全设备模板 `examples/stations/sim_virtual_station_tcp.json`（可选 `queue_capacity` 配置实时测量队列容量，默认 64；`pcn7-lt` / `dcn1000` 为黑体，而 `it6332a`、`gws-sten`、`dmm6500`、`detector-serial`、`cooler-modbus` 均支持 `host` TCP 与 `port` 串口二选一连接）；也可通过 `IR_ListSerialPorts` / `IR_ListCaptureDevices` 或 `ir_capture_accept --list` 枚举本机串口与可用相机，并用 `ir_capture_accept` 进行多轮启停或不停流拷机及并发预览压测。未被流程引用的设备不需要连接。流程文件支持 `schema_version: 1`（单批次 + 末尾 `save_raw`）与 `schema_version: 2`（多温点/多条件、`power_wait_stable`、`oven_stabilize`、`oven_standby`、`dmm_read`、`detector_timing`、`detector_gpol`、`detector_register`、`detector_current`、`cooler_read`、`flush_frames`、跨步像元图/掩码传递、开放 16 项 `IR_analysis` 方法含 `fft2d` 与高斯滤波/闪元检测参数、`save_raw` 可选或 `subdir` 多批归档、`repeat_burst` 周期无存盘流式写 CSV，以及 `safety.blackbody_standby` / `safety.oven_standby` 待机收尾，详见 `examples/recipes/virtual_station_hil_v2.json`）。`--check` 只检查 JSON、设备别名、步骤顺序、槽位类型、指标引用、单位和输出路径，不连接设备或创建结果目录。

运行时先取得实际画幅，再核对 ROI、单批大小和 SDK 在途图像存储额度。准备完成后才连接本配方引用的仪器。指标和归档顺序复用同一批完整像素。单批 RAW 像素默认上限为 256 MiB，可在工位文件的 `acquisition.max_batch_bytes` 调整；SDK 同时保留的采集队列、帧组、RAW 归档快照、像元图与掩码默认上限为 1 GiB，可用 `acquisition.max_inflight_bytes` 调整。算法临时工作区与操作系统/设备驱动缓存不计入该额度。

实时相机在仪器设定后、下一次取帧前会清空待处理帧；实时 `repeat_burst` 在每一轮间刷新待处理帧，RAW 回放则保持数据游标不变。预览通过 `IR_TryReadLatestFrame` 非阻塞读取，竞争时返回暂无预览帧，不会卡住测量取帧。应用可从其他线程调用 `IR_RequestStop`，SDK 由执行流程的线程完成停止、设备恢复和占用释放。

## 模拟设备

用 Python 标准库启动本机 TCP 黑体模拟器，Windows 和 Linux 均可：

```powershell
python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010
```

```bash
python3 simulators/ir_sim_devices.py blackbody-tcp --port 21010
```

另开一个终端，用 `sim_tcp.json` 和 `noise_blackbody.json` 运行 `ir_run_recipe`。加 `--unstable` 可以检查等稳超时和错误定位。

Linux 串口测试可启动模拟 PTY：

```bash
python3 simulators/ir_sim_devices.py power-pty
```

它会打印 `SDK_SERIAL_PORT=/dev/pts/...`。把该路径写入 `examples/stations/sim_power_serial.json` 的 `connection.port`，再运行 `power_serial_smoke.json`。模拟步骤只设定电压/限流并读取回读，不打开输出。Windows 串口测试需接一对虚拟 COM 端口（例如 `com0com`）：将其中一个端口填入工位配置，另一端通过虚拟串口服务连接模拟器。模拟器的 COM 模式使用可选 Python `pyserial`；该库只供开发模拟，不是 SDK 运行依赖。除 `simulators/ir_sim_devices.py` 单机模式（支持 `blackbody-*`、`power-tcp`/`-serial`/`-pty`、`oven-*`、`dmm6500-*`、`detector-*` 与 `cooler-*`）外，`1.6.0` 新增统一组合式虚拟工位 `simulators/ir_virtual_station.py`：
- `--mode tcp`：按 `examples/stations/sim_virtual_station_tcp.json` 默认端口同时拉起 6 类耦合设备，开箱可用 `ir_run_recipe` 跑通 `examples/recipes/virtual_station_hil_v2.json`；
- `--mode serial-map --config <映射.json>`：支持把电源/温箱/万用表/探测器/制冷机（`8N2`）分别映射到 Windows 虚拟 COM 端口，同时保持黑体走 TCP。

具体字段与可复制命令见[测试人员配方指南](测试人员配方指南.md)。

## 从 C 或 C++ 调用

`examples/CMakeLists.txt` 是客户侧独立工程。它从 `IR_SDK_ROOT` 加载公共头文件、导入库和运行库，构建纯 C（`ir_c_client`、`ir_analysis_c_sample`）、C++ 及 JSON 配方命令行样例：

```powershell
cmake -S .\examples -B .\build-client -DIR_SDK_ROOT="$PWD"
cmake --build .\build-client --config Release
```

```bash
cmake -S examples -B build-client -DIR_SDK_ROOT="$PWD"
cmake --build build-client --config Release
```

C/C++ 应用通过 `include/IR_station.h`、`IR_device.h`、`IR_analysis.h`、`IR_recipe.h` 与 `IR_plugin_abi.h`（外部算子插件契约）调用 C ABI。Windows 链接 `windows-x64/lib/*.lib`，部署 `windows-x64/bin/*.dll`。Linux 链接 `linux-x86_64/lib/*.so`，配套 CMake 会将库复制到示例程序目录。

配方调用传入 UTF-8 工位配置、配方文本和新结果目录。程序可在调用后直接读取失败阶段和帧数；如需实时订阅步骤进度，可改用 `IR_RunRecipeJsonEx` 传入 `IRRecipeRunOptions` 与 `IRRecipeStepCallback`。

```c
#include "IR_recipe.h"

/* station_json、recipe_json 和 output_directory 由应用准备。 */
IRRecipeResult run;
char error[1024];
int32_t status = IR_RunRecipeJson(station_json, recipe_json,
    output_directory, &run, error, sizeof error);
/* status 非 IR_OK 时检查 run.failed_stage、run.failed_step_index 和 run.cleanup_status。 */
```

## 从 C# 调用

`examples/csharp/IRSdkSample.csproj` 面向 .NET 10。它使用普通 P/Invoke，不需要 C++/CLI。`Program.cs` 与 `AnalysisInterop.cs` 提供原始帧、`IRStation.DeviceKind`、`BlackbodyReading`、`PowerReading`、`PowerCurrentStableSpec`、`OvenReading`、`DmmReading`、`DetectorCurrentReading`、`CoolerReading`、`Fft2dSummary` 与全部设备生命周期（`OpenDevice`/`CloseDevice`、黑体/电源等稳`WaitPowerCurrentStable`/烘箱/万用表/探测器/制冷机）及 `Fft2dMagnitudeF64` P/Invoke 声明，可直接作为业务程序的起点。

原始帧 C ABI 样例：

```powershell
$env:IR_SDK_LIB_DIR = (Resolve-Path '.\windows-x64\bin').Path
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- .\examples\data\raw16 .\output\csharp-run
```

Ubuntu：

```bash
export IR_SDK_LIB_DIR="$PWD/linux-x86_64/lib"
dotnet run --project examples/csharp/IRSdkSample.csproj -- examples/data/raw16 output/csharp-run
```

JSON 流程由同一个 C ABI 执行：

```powershell
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- --recipe .\examples\stations\offline.json .\examples\recipes\noise_roi.json ..\output\csharp-recipe-run
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- --analysis
```

```bash
dotnet run --project examples/csharp/IRSdkSample.csproj -- --recipe examples/stations/offline.json examples/recipes/noise_roi.json ../output/csharp-recipe-run
dotnet run --project examples/csharp/IRSdkSample.csproj -- --analysis
```

python .\examples\python\ir_noise.py .\examples\data\raw16

## 多线程和错误处理

一进程同时运行一条配方。打开、启动、取帧、停止、关闭和流程由同一个工作线程执行，其他线程可调用 `IR_RequestStop`；同时可通过 `IR_TryReadLatestFrame` 与 `IR_GetCaptureStats` 无阻塞获取最新预览帧与 `FrameQueue` 统计，不与正在运行的测量或配方互斥。取帧结束后，原线程先停流并执行配方声明的收尾，再释放仪器。分析和写盘期间其他配方及采集写控制调用仍返回 `IR_BUSY`。独立的 `IR_analysis` 调用可在其他线程使用各自的输出缓冲区。

检查 `IRStatus` 和错误文本。JSON 流程通过 `IRRecipeResult` 返回连续完成帧数、失败阶段、从 0 开始的步骤下标和收尾状态。执行失败与收尾失败可以同时出现。应用应分别处理这两个状态。测量完整但超出产品限值时，C ABI 返回 `IR_OK`，命令行返回 20，`result.json` 记为 `NG`。从早期候选包升级调用时，使用本包的头文件和语言声明重新编译或更新绑定。
