# IR SDK 客户接入说明

## 包内目录

| 目录 | 内容 |
|---|---|
| `include/` | 稳定的 C 接口头文件 |
| `windows-x64/bin/` | `IR_station.dll`、`IR_analysis.dll` 和配方命令行 |
| `windows-x64/lib/` | MSVC 导入库，供客户编译 C/C++ 程序 |
| `linux-x86_64/lib/` | `libIR_station.so` 和 `libIR_analysis.so` |
| `linux-x86_64/bin/` | Linux 配方命令行 |
| `examples/stations/`、`examples/recipes/`、`examples/data/` | 工位模板、配方和离线 RAW16 样例 |
| `examples/` | C、C++、C# 和 Python 调用样例 |
| `docs/` | 本说明、开发规范、设备支持矩阵和验证记录 |

应用随目标平台部署两个 SDK 库。Station 会加载同目录的 Analysis。包中没有 Qt、Asio 或 JSON 运行库。Windows 客户机需要安装相应的 MSVC x64 Runtime；Linux 需要系统 C/C++ 运行库。

## 第一次离线运行

工位连接与测试步骤分成两份 JSON。在解压后的包根目录先做只读预检，再运行随包离线样例。Linux 使用能保留执行权限的工具解包，例如 `unzip` 或 `cmake -E tar xf`。

```powershell
& '.\windows-x64\bin\ir_run_recipe.exe' --check --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\offline-run'
& '.\windows-x64\bin\ir_run_recipe.exe' --run --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\offline-run'
```

```bash
./linux-x86_64/bin/ir_run_recipe --check --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/offline-run
./linux-x86_64/bin/ir_run_recipe --run --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/offline-run
```

首跑输入为两帧 `1×1` RAW16。全图和 ROI 均值都是 `21 DN`，时域噪声约 `1.4142135623730951 DN`，判定为 `PASS`。练习 ROI 时换用 `examples/stations/roi_2x2.json` 与 `examples/recipes/noise_roi_2x2.json`，新输出目录中的全图均值应为 `51 DN`，左列为 `41 DN`。结果目录包含 `frames.raw`、`frames.csv`、`result.json`，每次使用一个尚不存在的新目录。

RAW 源路径相对工位 JSON；输出路径相对流程 JSON。SDK C ABI 接收 UTF-8 JSON 字符串，C# 和 Python 不需要 JSON 原生库依赖。

## 工位文件与测试流程

工位文件维护采集源及设备连接，例如 `examples/stations/sim_tcp.json`。未被流程引用的设备不需要连接。流程文件按顺序写入黑体等稳、串口电源设定/回读、采集、分析、限值和归档步骤。首版支持 `blackbody_stabilize`、`power_set`、`power_output`、`power_read`、`capture`、`analyze`、`save_raw`。`--check` 只检查 JSON、设备别名、字段、步骤次序、指标引用、单位和输出路径，不连接设备或创建结果目录。

运行时先取得实际画幅，再核对 ROI 和 RAW 缓冲额度。准备完成后才连接本配方引用的仪器。指标和归档顺序复用同一批完整像素。每次运行的 RAW 像素默认上限为 256 MiB，可在工位文件的 `acquisition.max_batch_bytes` 调整。帧标记和算法临时数组另占内存。

## 模拟设备

用 Python 标准库启动本机 TCP 黑体模拟器，Windows 和 Linux 均可：

```powershell
& 'D:\CS\py\.venv_3_12\Scripts\python.exe' .\simulators\ir_sim_devices.py blackbody-tcp --port 21010
```

```bash
python3 simulators/ir_sim_devices.py blackbody-tcp --port 21010
```

另开一个终端，用 `sim_tcp.json` 和 `noise_blackbody.json` 运行 `ir_run_recipe`。加 `--unstable` 可以检查等稳超时和错误定位。

Linux 串口测试可启动模拟 PTY：

```bash
python3 simulators/ir_sim_devices.py power-pty
```

它会打印 `SDK_SERIAL_PORT=/dev/pts/...`。把该路径写入 `examples/stations/sim_power_serial.json` 的 `connection.port`，再运行 `power_serial_smoke.json`。模拟步骤只设定电压/限流并读取回读，不打开输出。Windows 串口测试需接一对虚拟 COM 端口；模拟脚本通过可选的 pyserial 访问其中一端，SDK 本身不依赖 pyserial。

具体字段与可复制命令见[测试人员配方指南](测试人员配方指南.md)。

## 从 C 或 C++ 调用

`examples/CMakeLists.txt` 是客户侧独立工程。它从 `IR_SDK_ROOT` 加载公共头文件、导入库和运行库，构建纯 C、C++ 及 JSON 配方命令行样例：

```powershell
cmake -S .\examples -B .\build-client -DIR_SDK_ROOT="$PWD"
cmake --build .\build-client --config Release
```

```bash
cmake -S examples -B build-client -DIR_SDK_ROOT="$PWD"
cmake --build build-client --config Release
```

C/C++ 应用通过 `include/IR_station.h`、`IR_device.h`、`IR_analysis.h` 和 `IR_recipe.h` 调用 C ABI。Windows 链接 `windows-x64/lib/*.lib`，部署 `windows-x64/bin/*.dll`。Linux 链接 `linux-x86_64/lib/*.so`，配套 CMake 会将库复制到示例程序目录。

配方调用传入 UTF-8 工位配置、配方文本和新结果目录。程序可在调用后直接读取失败阶段和帧数。

```c
#include "IR_recipe.h"

/* station_json、recipe_json 和 output_directory 由应用准备。 */
IRRecipeResult run;
char error[1024];
int32_t status = IR_RunRecipeJson(station_json, recipe_json,
    output_directory, &run, error, sizeof error);
/* status 非 IR_OK 时检查 run.failed_stage、run.failed_step_index 和 run.cleanup_status。 */
```

## 从 C# 调用

`examples/csharp/IRSdkSample.csproj` 面向 .NET 10。它使用普通 P/Invoke，不需要 C++/CLI。结构体布局、`ulong` 句柄和 UTF-8 字符串的写法可直接作为业务程序的起点。

原始帧 C ABI 样例：

```powershell
$env:IR_SDK_LIB_DIR = (Resolve-Path '.\windows-x64\bin').Path
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- .\examples\data\raw16 .\output\csharp-run
```

Ubuntu：

```bash
export IR_SDK_LIB_DIR="$PWD/linux-x86_64/lib"
dotnet run --project examples/csharp/IRSdkSample.csproj -- examples/data/raw16 output/csharp-run
```

JSON 流程由同一个 C ABI 执行：

```powershell
dotnet run --project .\examples\csharp\IRSdkSample.csproj -- --recipe .\examples\stations\offline.json .\examples\recipes\noise_roi.json ..\output\csharp-recipe-run
```

```bash
dotnet run --project examples/csharp/IRSdkSample.csproj -- --recipe examples/stations/offline.json examples/recipes/noise_roi.json ../output/csharp-recipe-run
```

## 多线程和错误处理

一进程同时运行一条配方。打开、启动、取帧、停止、关闭和流程由同一个工作线程执行，其他线程可调用 `IR_RequestStop`。取帧结束后，原线程先停流并执行配方声明的收尾，再释放仪器。分析和写盘期间其他配方及采集调用仍返回 `IR_BUSY`。独立的 `IR_analysis` 调用可在其他线程使用各自的输出缓冲区。

检查 `IRStatus` 和错误文本。JSON 流程通过 `IRRecipeResult` 返回连续完成帧数、失败阶段、从 0 开始的步骤下标和收尾状态。执行失败与收尾失败可以同时出现。应用应分别处理这两个状态。测量完整但超出产品限值时，C ABI 返回 `IR_OK`，命令行返回 20，`result.json` 记为 `NG`。从早期 1.1.0 候选包升级配方调用时，使用本包的头文件和语言声明重新编译或更新绑定。
