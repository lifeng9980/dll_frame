# 测试人员配方指南

测试配方由两个 UTF-8 JSON 文件组成：工位文件描述本机有什么设备及如何连接；流程文件描述这次测量按什么顺序做什么。测试人员只需要复制模板、调整设备别名、帧数和限值，不需要改 SDK 源码。

## 1. 文件分别负责什么

| 文件 | 放什么 | 示例 |
|---|---|---|
| 工位配置 | 采集后端和来源、像素有效位、可选设备及连接参数 | [`offline.json`](../examples/stations/offline.json)、[`roi_2x2.json`](../examples/stations/roi_2x2.json)、[`sim_tcp.json`](../examples/stations/sim_tcp.json) |
| 测试流程 | 黑体等稳、电源通道操作、采集帧数、要算的指标、限值和归档（支持 v1 单批及 v2 多条件/无存盘） | [`noise_roi.json`](../examples/recipes/noise_roi.json)、[`noise_blackbody.json`](../examples/recipes/noise_blackbody.json)、[`nodisk_roi_v2.json`](../examples/recipes/nodisk_roi_v2.json) |
| Schema 校验 | 编辑器字段提示与静态校验规则（Draft 2020-12） | [`station.schema.json`](../examples/schemas/station.schema.json)、[`recipe.schema.json`](../examples/schemas/recipe.schema.json)、[`recipe.v2.schema.json`](../examples/schemas/recipe.v2.schema.json) |

工位与流程 JSON 顶层均支持可选字符串字段 `"$schema"`，随包模板已指向 `examples/schemas/`，在 VS Code 等编辑器中打开即可获得字段补全与静态提示。工位文件里的相对 RAW 路径相对该工位文件所在目录。流程中的结果目录相对流程文件所在目录。输出必须是已存在父目录下面的新目录，SDK 不覆盖历史结果。

## 2. 预检与运行

先运行 `--check`，通过后再运行 `--run`。两次使用相同的新输出目录：

```powershell
& '.\windows-x64\bin\ir_run_recipe.exe' --check --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\my-first-run'
& '.\windows-x64\bin\ir_run_recipe.exe' --run --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\my-first-run'
```

```bash
./linux-x86_64/bin/ir_run_recipe --check --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/my-first-run
./linux-x86_64/bin/ir_run_recipe --run --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/my-first-run
```

`--check` 不打开相机或仪器，也不创建结果。它检查 JSON 字段、设备别名、步骤顺序、指标引用、单位和输出路径。`--run` 用实际画幅检查 ROI 和 RAW 缓冲额度，然后连接配方引用的仪器。

离线首跑应得到两帧、全图和 ROI 均值 `21 DN`。练习修改 ROI 时，换用 `roi_2x2.json` 和 [`noise_roi_2x2.json`](../examples/recipes/noise_roi_2x2.json)，全图均值为 `51 DN`，左列为 `41 DN`。

## 3. 连接模拟黑体

开一个终端启动本机 PCN7-LT 模拟器，另一个终端运行模板流程：

```powershell
python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010
```

```bash
python3 simulators/ir_sim_devices.py blackbody-tcp --port 21010
```

在另一个终端执行：

```text
ir_run_recipe --check --station examples/stations/sim_tcp.json --recipe examples/recipes/noise_blackbody.json --output ../output/blackbody-pass
ir_run_recipe --run   --station examples/stations/sim_tcp.json --recipe examples/recipes/noise_blackbody.json --output ../output/blackbody-pass
```

模拟器支持多种设备模式与故障注入/收发日志参数，便于验证重连、分片重组和失败收尾（覆盖 `power-tcp`、`oven-*`、`dmm6500-*`、`detector-*`、`cooler-*` 等单机模式及 `--cooler-profile`、`--cooler-mv`、`--slave-address`、`--bad-crc`、`--address`、`--alarm`、`--dmm-mode`、`--dmm-value`、`--bad-ack` 参数）；若需一次性联调 6 类存在物理耦合的仪器，可使用 `python .\simulators\ir_virtual_station.py --mode tcp` 配对 [`sim_virtual_station_tcp.json`](../examples/stations/sim_virtual_station_tcp.json) 与 [`virtual_station_hil_v2.json`](../examples/recipes/virtual_station_hil_v2.json)（Windows 虚拟 COM 对可使用 `--mode serial-map --config <端口映射.json>`）：

- `--drop-command <命令>` 与 `--drop-count <次数>`：丢弃指定命令的应答（黑体可传 DOC058 功能码如 `114`、`write:97` 或别名 `temp`、`set`、`stable`；电源可传 SCPI 命令如 `VOLT?`）。未显式传 `--drop-count` 时默认丢弃 1 次。
- `--fragment`：将应答拆成带短延迟的小分片发送，验证传输层报文重组。
- `--log-io`：打印收到的请求、触发的丢包以及发出的应答。

例如在 Windows 下验证单次读温应答丢失并分片重连恢复：

```powershell
python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010 --drop-command 114 --drop-count 1 --fragment --log-io
```

要检查异常停止，重启模拟器时加 `--unstable`（或将 `--drop-count` 设为大于重连上限的值），将流程中的 `timeout_ms` 临时设为较短时间，再运行到一个新目录。预检应通过；运行应返回等稳超时或通信异常，且不生成结果目录。未参与流程的设备不要写入 `steps`，SDK 就不会要求连接它。

## 4. 连接模拟串口电源

Linux/WSL 可以由模拟器自己创建一对伪终端：

```bash
python3 simulators/ir_sim_devices.py power-pty
```

它会打印 `SDK_SERIAL_PORT=/dev/pts/...`。把打印的设备路径填入 `examples/stations/sim_power_serial.json` 的 `devices.supply.connection.port`。运行 `power_serial_smoke.json` 会依次设定 CH1 的 12 V/2 A、读回并采集 RAW；它不会打开通道输出。

用同一模拟工位运行 [`power_serial_output_cycle.json`](../examples/recipes/power_serial_output_cycle.json) 可以练习开输出与收尾。打开输出时，步骤必须同时声明 `"enabled": true` 和 `"off_after_run": true`。成功、失败或取消时，SDK 都在停流后发出关闭命令并回读确认。把示例的采集帧数改为 3 可复现提前结束，CLI 应报告已完成 2 帧、收尾状态 0，结果目录不会发布。

Windows 串口模拟需要虚拟 COM 端口对：将其中一个端口填入工位配置，另一端通过虚拟串口服务连接模拟器。模拟器的 COM 模式使用可选 Python `pyserial`；该库只供开发模拟，不是 SDK 运行依赖。没有虚拟 COM 对时，Windows 可先运行 TCP 黑体与离线 RAW 配方，不能把 WSL PTY 结果当作 Windows 串口验收。

## 5. 查看结果和判定

成功归档生成：

| 文件 | 内容 |
|---|---|
| `frames.raw` | 连续完整的 RAW16 帧，按帧、行、列紧密排列 |
| `frames.csv` | 几何、有效位、帧序号及可用时间信息 |
| `result.json` | 实际配方、设备回读、采集来源、指标及方法版本、`station_version`/`analysis_version`/`source_commit`/`started_utc`/`finished_utc` 追溯字段、收尾状态和限值判定 |

`run_status=PASS` 表示本次测量完整且配置的所有限值通过；`NG` 表示测量完整但至少一项产品限值未满足；没有限值时为 `COMPLETED`。`NG` 时 CLI 返回退出码 20，C ABI 仍返回 `IR_OK`，可从 `result.json` 读取判定。连接失败、超时、缺帧、取消或归档失败属于测量执行错误，不应作为产品 `NG` 使用。另外，`result.json` 中的 `recipe` 字段原样保存原始配方内容，其中的相对 `"$schema"` 引用仍相对原配方文件所在目录，而不相对输出目录。

执行取消或异常时，CLI 仍会在标准输出打印统一的 `run_status=CANCELLED`（对应 `IR_CANCELLED`）或 `run_status=ERROR` 及 `completed_frames`，并在标准错误保留 `status`、`stage`、`step_index`、`completed_frames`、`cleanup_status` 诊断字段与原退出码。步骤下标从 0 开始，`-1` 表示不属于某个步骤。收尾状态为 0 表示确认成功或无需收尾。有收尾错误时，先确认设备状态再试。应用可从其他线程调用 `IR_RequestStop`，随后等待流程所在工作线程完成清理和返回；同一流程占用的采集源或仪器不会被其他线程的设定、读取或关闭操作抢用，调用返回 `IR_BUSY`。直接中止进程时，SDK 无法执行收尾代码。

普通流程只有成功后才发布完整结果目录。`repeat_burst` 会在第一行摘要写入前独占创建结果目录，以免两个运行覆盖同一路径；运行中取消时保留已经刷盘的 CSV 行，但不会生成 `result.json`。

`max_batch_bytes` 默认允许 256 MiB 的单批 RAW 像素（1280×1024、1000 帧的像素约需 2.44 GiB）；`max_inflight_bytes` 默认 1 GiB，限制 SDK 同时保留的采集队列、帧组、`save_raw` 快照、像元图和掩码，配方会在控制仪器前预估是否超限。重复写入同一帧组槽位按其最大帧数计一次，每个 `save_raw` 步骤会按归档批次另计一份快照空间。算法临时工作区和操作系统/驱动内部缓存不计入这个估算；`queue_capacity` 默认 64 帧（范围 2~4096）。

流程控制仪器后，实时相机下一次取帧前会丢弃 SDK 队列中的待处理帧；实时 `repeat_burst` 每轮也会刷新待处理帧。RAW 回放不因仪器控制而跳过数据，只有配方显式使用 `flush_frames` 才移动回放位置。`IR_TryReadLatestFrame` 是非阻塞预览接口，预览读写竞争时会暂时返回“无新帧”，不影响测量队列。

## 6. Schema v2 多条件编排与无存盘温漂循环

`schema_version: 2`（见 [`recipe.v2.schema.json`](../examples/schemas/recipe.v2.schema.json)）完全兼容 v1 工位配置与 CLI 调用方式，新增能力如下：
- **多条件与可选落盘**：可按序交错多个 `blackbody_stabilize` / `power_*`（含 `power_wait_stable` 等待电源启动冲击后进入低稳态电流区间） / `oven_stabilize`（可选 `standby_after_run: true`） / `oven_standby` / `dmm_read`（可选 `set_mode: true` 与 `mode` 取 `dcv`/`dci`/`res`/`diode`，输出 `<name>.value` 参与 `limits` 或 `repeat_burst` 的 `record_metrics`） / `detector_timing` / `detector_gpol` / `detector_register`（通过 `command_code` + `payload_hex` 下发任意 `0xCC` 指令） / `detector_current`（读取 24 位 ADC 电流，产出 `<name>.current_ma` 与 `<name>.sense_voltage_v`） / `cooler_read`（Modbus RTU 读取制冷机电压，产出 `<name>.voltage_mv`） / `flush_frames` / `capture`（通过 `"output"` 命名批次）与 `analyze`；`save_raw` 可省略（无存盘，`raw_saved: false`，如 [`nodisk_roi_v2.json`](../examples/recipes/nodisk_roi_v2.json)）或按 `"subdir"` 归档多个批次。
- **可组合算子数据流**：`analyze` 支持 `"inputs"` / `"outputs"` 槽位传递像元图（`double_map`）、掩码（`byte_mask`）和标定上下文（`drift_ctx`），并开放 `"params"` 参数对象，已接入 `temporal_noise`、`roi_mean`、`frame_stats`、`map_summary`、`two_point_nuc`、`spatial_filter`（支持 `"filter_kind": "box_mean" | "gaussian"`）、`map_binary_op`、`threshold_mask`、`mask_combine`、`gb_evaluate`、`gjb_evaluate`、`gjb_burst`、`noise3d_compute`、`channel_spectrum`、`flicker_detect`、`fft2d`（支持 `window` 取 `rect`/`rectangular`/`hann`、`detrend_mean`、`shift_dc_center`，可选输出 `magnitude_map`/`power_map` 及 `dc_magnitude`/`peak_ac_magnitude`/`total_ac_power`/`low_freq_power_ratio`/`high_freq_power_ratio`）共 16 项方法。
- **周期循环 `repeat_burst`**：按 `max_iterations` / `duration_sec` / `interval_sec` 不停流周期采帧并实时向 `csv_file`（默认 `burst_summary.csv`）刷入每组摘要行，中断/取消时保留已刷盘数据。
- **安全待机收尾**：`safety.blackbody_standby` 可配置结束/异常/取消时自动把黑体设回待机温度；`safety.oven_standby` 可列出烘箱别名（或结合 `oven_stabilize` 的 `standby_after_run`），在结束、失败或取消时自动切回 `STANDBY`。
- **端口与采帧前置验收**：使用 `ir_capture_accept --list` 查询本机串口与实时相机名，并可用 `ir_capture_accept --backend directshow --source FX3 --frames 100 --cycles 20 --preview-ms 20 --report accept.json` 做启停或不停流（`--flush-between N`）拷机验收。
