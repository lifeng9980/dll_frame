# 测试人员配方指南

测试配方由两个 UTF-8 JSON 文件组成：工位文件描述本机有什么设备及如何连接；流程文件描述这次测量按什么顺序做什么。测试人员只需要复制模板、调整设备别名、帧数和限值，不需要改 SDK 源码。

## 1. 文件分别负责什么

| 文件 | 放什么 | 示例 |
|---|---|---|
| 工位配置 | 采集后端和来源、像素有效位、可选设备及连接参数 | [`offline.json`](../examples/stations/offline.json)、[`roi_2x2.json`](../examples/stations/roi_2x2.json)、[`sim_tcp.json`](../examples/stations/sim_tcp.json) |
| 测试流程 | 黑体等稳、电源通道操作、采集帧数、要算的指标、限值和归档 | [`noise_roi.json`](../examples/recipes/noise_roi.json)、[`noise_blackbody.json`](../examples/recipes/noise_blackbody.json) |
| Schema 校验 | 编辑器字段提示与静态校验规则（Draft 2020-12） | [`station.schema.json`](../examples/schemas/station.schema.json)、[`recipe.schema.json`](../examples/schemas/recipe.schema.json) |

工位与流程 JSON 顶层均支持可选字符串字段 `"$schema"`，随包模板已指向 `examples/schemas/`，在 VS Code 等编辑器中打开即可获得字段补全与静态提示。工位文件里的相对 RAW 路径相对该工位文件所在目录。流程中的结果目录相对流程文件所在目录。输出必须是已存在父目录下面的新目录，SDK 不覆盖历史结果。

## 2. 预检与运行

先运行 `--check`，通过后再运行 `--run`。两次使用相同的新输出目录：

```powershell
& '.\windows-x64\bin\ir_run_recipe.exe' --check --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\my-first-run'
& '.\windows-x64\bin\ir_run_recipe.exe' --run --station '.\examples\stations\offline.json' --recipe '.\examples\recipes\noise_roi.json' --output '..\output\my-first-run'
```

```bash
./linux-x86_64/bin/ir_run_recipe --check --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/my-first-run
./linux-x86_64/bin/ir_run_recipe --run --station examples/stations/offline.json --recipe examples/recipes/noise_roi.json --output ../output/my-first-run
```

`--check` 不打开相机或仪器，也不创建结果。它检查 JSON 字段、设备别名、步骤顺序、指标引用、单位和输出路径。`--run` 用实际画幅检查 ROI 和 RAW 缓冲额度，然后连接配方引用的仪器。

离线首跑应得到两帧、全图和 ROI 均值 `21 DN`。练习修改 ROI 时，换用 `roi_2x2.json` 和 [`noise_roi_2x2.json`](../examples/recipes/noise_roi_2x2.json)，全图均值为 `51 DN`，左列为 `41 DN`。

## 3. 连接模拟黑体

开一个终端启动本机 PCN7-LT 模拟器，另一个终端运行模板流程：

```powershell
python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010
```

```bash
python3 simulators/ir_sim_devices.py blackbody-tcp --port 21010
```

在另一个终端执行：

```text
ir_run_recipe --check --station examples/stations/sim_tcp.json --recipe examples/recipes/noise_blackbody.json --output ../output/blackbody-pass
ir_run_recipe --run   --station examples/stations/sim_tcp.json --recipe examples/recipes/noise_blackbody.json --output ../output/blackbody-pass
```

模拟器支持故障注入与收发日志参数，便于验证重连、分片重组和失败收尾：

- `--drop-command <命令>` 与 `--drop-count <次数>`：丢弃指定命令的应答（黑体可传 DOC058 功能码如 `114`、`write:97` 或别名 `temp`、`set`、`stable`；电源可传 SCPI 命令如 `VOLT?`）。未显式传 `--drop-count` 时默认丢弃 1 次。
- `--fragment`：将应答拆成带短延迟的小分片发送，验证传输层报文重组。
- `--log-io`：打印收到的请求、触发的丢包以及发出的应答。

例如在 Windows 下验证单次读温应答丢失并分片重连恢复：

```powershell
python .\simulators\ir_sim_devices.py blackbody-tcp --port 21010 --drop-command 114 --drop-count 1 --fragment --log-io
```

要检查异常停止，重启模拟器时加 `--unstable`（或将 `--drop-count` 设为大于重连上限的值），将流程中的 `timeout_ms` 临时设为较短时间，再运行到一个新目录。预检应通过；运行应返回等稳超时或通信异常，且不生成结果目录。未参与流程的设备不要写入 `steps`，SDK 就不会要求连接它。

## 4. 连接模拟串口电源

Linux/WSL 可以由模拟器自己创建一对伪终端：

```bash
python3 simulators/ir_sim_devices.py power-pty
```

它会打印 `SDK_SERIAL_PORT=/dev/pts/...`。把打印的设备路径填入 `examples/stations/sim_power_serial.json` 的 `devices.supply.connection.port`。运行 `power_serial_smoke.json` 会依次设定 CH1 的 12 V/2 A、读回并采集 RAW；它不会打开通道输出。

用同一模拟工位运行 [`power_serial_output_cycle.json`](../examples/recipes/power_serial_output_cycle.json) 可以练习开输出与收尾。打开输出时，步骤必须同时声明 `"enabled": true` 和 `"off_after_run": true`。成功、失败或取消时，SDK 都在停流后发出关闭命令并回读确认。把示例的采集帧数改为 3 可复现提前结束，CLI 应报告已完成 2 帧、收尾状态 0，结果目录不会发布。

Windows 串口模拟需要虚拟 COM 端口对：将其中一个端口填入工位配置，另一端通过虚拟串口服务连接模拟器。模拟器的 COM 模式使用可选 Python `pyserial`；该库只供开发模拟，不是 SDK 运行依赖。没有虚拟 COM 对时，Windows 可先运行 TCP 黑体与离线 RAW 配方，不能把 WSL PTY 结果当作 Windows 串口验收。

## 5. 查看结果和判定

成功归档生成：

| 文件 | 内容 |
|---|---|
| `frames.raw` | 连续完整的 RAW16 帧，按帧、行、列紧密排列 |
| `frames.csv` | 几何、有效位、帧序号及可用时间信息 |
| `result.json` | 实际配方、设备回读、采集来源、指标及方法版本、`station_version`/`analysis_version`/`source_commit`/`started_utc`/`finished_utc` 追溯字段、收尾状态和限值判定 |

`run_status=PASS` 表示本次测量完整且配置的所有限值通过；`NG` 表示测量完整但至少一项产品限值未满足；没有限值时为 `COMPLETED`。`NG` 时 CLI 返回退出码 20，C ABI 仍返回 `IR_OK`，可从 `result.json` 读取判定。连接失败、超时、缺帧、取消或归档失败属于测量执行错误，不应作为产品 `NG` 使用。另外，`result.json` 中的 `recipe` 字段原样保存原始配方内容，其中的相对 `"$schema"` 引用仍相对原配方文件所在目录，而不相对输出目录。

执行取消或异常时，CLI 仍会在标准输出打印统一的 `run_status=CANCELLED`（对应 `IR_CANCELLED`）或 `run_status=ERROR` 及 `completed_frames`，并在标准错误保留 `status`、`stage`、`step_index`、`completed_frames`、`cleanup_status` 诊断字段与原退出码。步骤下标从 0 开始，`-1` 表示不属于某个步骤。收尾状态为 0 表示确认成功或无需收尾。有收尾错误时，先确认设备状态再试。应用请求取消时调用 `IR_RequestStop` 并等待运行返回。直接中止进程时，SDK 无法执行收尾代码。运行失败不发布结果目录。

`max_batch_bytes` 默认允许 256 MiB 的 RAW 像素。1280×1024、1000 帧的像素约需 2.44 GiB，帧标记和计算临时数组另占内存。一次运行只采一批，指标与归档顺序使用同一份只读像素。
