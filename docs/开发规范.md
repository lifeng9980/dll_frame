# IR SDK 开发规范

## 目录与职责

| 需要新增的能力 | 加入位置 | 对外输入和输出 |
|---|---|---|
| 一种仪器型号或协议 | `station/instruments/<device>/` | 型号、连接参数、控制命令和设备回读；共用 `station/instruments/transport/` 的 Asio TCP/串口通信 |
| 一种相机或采集卡 | `station/acquisition/<backend>/`，实现 `FrameSource` | 打开源后返回实际几何，取帧时交付 RAW16 像素、帧标记和状态 |
| 基础像素运算或标准指标 | `analysis/` | 输入帧组、条件和算法参数；输出指标、单位和版本 |
| 一条自动测试流程 | `station/procedures/` | 组合设备目标状态、采集时机、计算、保存与失败收尾 |
| 应用界面、产品阈值或工单逻辑 | SDK 之外的研发/量产应用 | 通过 C ABI 或 JSON 配方命令行调用 SDK |

`IR_station` 包含仪器、采集和流程。`IR_analysis` 包含可独立使用的计算。现阶段维持两个动态库，不为每个设备型号或算法再拆 DLL。

## 公共接口和 ABI

- 新增调用入口写在 `include/IR_*.h`，使用 `extern "C"`、固定宽度整数和明确的指针/缓冲区长度，不把 C++ 类、Qt 类型或第三方 JSON 类型暴露给调用者。
- 字符串参数按 UTF-8 传递。结构体字段顺序和类型一经发布即作为 ABI；需要变更时同步更新 C、C#、Python 三种声明和布局验收。
- 输出内存由调用者分配。函数文档写清单位、像元/帧顺序、容量、线程要求、超时和失败时哪些输出有效。
- 所有错误以 `IRStatus` 返回。实现内部的 C++ 异常必须在 C ABI 边界转换为状态码和 UTF-8 错误文本。
- 新公开函数必须有一个最小 C 样例，说明输入、输出和资源释放顺序。

## 仪器接入

设备型号驱动只处理该型号的命令编码、应答解释、设备身份和回读。通用串口/TCP 超时与收发留在 Asio transport。配置中的串口号、TCP 地址、VISA 资源名等只在打开时传入。

驱动要说明设备断开后哪些查询可以安全重试。设备在流程内被预约时，其他线程对同一句柄的操作返回 `IR_BUSY`。设备响应明确断连或通信错误时，按协议等待并有限重连；无法恢复则流程报告步骤、已完成帧和收尾状态，不继续使用旧数据。

## 相机接入

新后端实现 `FrameSource` 的打开、开始、读取、停止和关闭。后端负责厂商缓冲区生命周期、行跨度、方向、字节序和 RAW16 解包；算法层只收到紧密排列的 `[帧][行][列]` `uint16_t` 像素。后端不能把原始探测器数据先做 RGB/YUV 灰度转换。

帧号或时间戳没有来源时不要伪造。能识别缺帧时返回相应状态，并保留 `completed` 指示的连续有效前缀。增加 Windows 或 Linux 后端时同时更新 CMake 平台选择和设备支持矩阵。NI-IMAQ 1433 暂不实现；确认驱动和 API 后再作为 Windows 后端接入，Linux 支持另行验证。

## 算法和指标

基础计算与 GJB、EMVA 等标准方法分层放在 `analysis/`。每个标准指标注明编号、版本、条款、必需帧组、实测条件、单位、参考数据和容差。算法不能从 SDK 外部猜测产品判定限值。

新增算法先用小的已知数组验证数值，再用离线 RAW 复算。相同输入的 Windows/Linux 结果必须在预先声明的浮点容差内一致。OpenCV 只在方法确实需要时引入；当前 SDK 不依赖 OpenCV。

## 流程、线程与资源

配方由 `recipe_config.cpp` 解析成有类型的步骤，`recipe_metrics.cpp` 集中登记方法的参数和输出，`recipe_json.cpp` 协调执行。`IR_CheckRecipeJson` 做静态预检。`IR_RunRecipeJson` 用实际画幅检查 ROI 和 RAW 缓冲额度，准备成功后只打开并预约本次使用的仪器。

同一流程只采集一个批次，多个指标和归档顺序复用同一份只读 RAW16。像素默认上限 256 MiB，由工位配置调整，帧标记和分析内存另计。

采集和流程在同一工作线程执行。`Measurement` 持有整次运行的采集占用与停止范围，分析和归档期间继续拒绝并发配方。其他线程可以调用 `IR_RequestStop`，当前同步事务结束时检查取消。取帧后先停流，再执行配方声明的设备收尾并释放仪器。`IRRecipeResult` 分别记录执行阶段、步骤下标、完成帧数和收尾状态。离线 Analysis 可并行运行，每次调用持有自己的输出缓冲区。

## 第三方库和构建

SDK 运行包只交付两个 IR 动态库和示例程序。Qt 不进入实现或运行依赖。Asio 1.36.0 和 nlohmann/json 3.12.0 是私有构建期头文件依赖，不作为 C ABI 的数据类型，也不要求客户部署动态库。没有明确功能收益时不增加第三方运行库。

改动 Station 或 Analysis 后，从同一提交分别用 MSVC x64 与 Ubuntu 24.04 x86_64 编译。完成 CTest，再用安装目录的头文件、导入库和动态库独立编译 C/C++ 样例；C# 与 Python 示例在目标平台各跑一次。检查运行依赖、输出路径、错误状态和支持矩阵。新硬件要区分“编译通过”“模拟通过”和“真机通过”。配方步骤扩展须同时验证 `--check` 与 `--run`；新增算法须用小数组固定预期值并验证离线数据。
