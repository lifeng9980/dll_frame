# 算法接入指南

新增基础运算或测试指标放入 `analysis/`，公开的调用函数放入 `include/IR_analysis.h`。`IR_analysis` 不控制仪器、不打开相机，也不判定产品是否合格；输入缓冲区由调用方持有，单位和算法版本由接口或结果记录说明。

## 三层权责边界

- **核心层（SDK 维护者）**：维护 `include/IR_*.h` C ABI 稳定性、仪器/采集/流程框架与基础像素算子。
- **扩展层（算法贡献者）**：在 `analysis/` 实现零 Qt、零 OpenCV 的纯 C++20 指标函数，配套 `sdk_tests/` 小数组手算与离线复算用例，并在需要配方调用时登记到 `station/procedures/recipe_metrics.cpp`。
- **配方/应用层（测试与业务侧）**：在 JSON 配方中引用已登记的指标名与参数、维护产品限值，不修改 SDK 源码。

## 标准差与掩码口径约定

- **既有 `IR_RunNoise` 与配方 `temporal_noise`（分母 `N - 1`）**：调用 `IR_FrameStatisticsU16(..., sample_std = 1)` 计算逐像元样本标准差的全图均值（`mean_pixel_sample_std`）。该口径已发布并保持向后兼容，不得修改。
- **GJB 噪声图 `vn`（分母 `N`）**：已确认为逐像元**总体标准差**（`IR_FrameStatisticsU16(..., sample_std = 0)`，分母 `N`），与 `optmeas-usb/autotest/BurstStatistics` 口径一致。后续 GJB 指标将以独立 C API 与独立配方方法名交付，与既有 `temporal_noise_dn` 明确区分。
- **坏元 / 有效像元掩码**：需要掩码输入的指标统一采用紧密排列的 `[行][列]` `uint8_t` 数组，由调用方分配并在 C 头文件注释中明确有效/坏元取值（例如 `0 = 有效像元，非 0 = 坏元/排除`）及空掩码行为（`mask == NULL` 表示全图有效）。

## 算法规格卡（新增指标必填）

每个新指标在编码前需填写下表并随代码评审一并提交：

| 字段 | 说明与示例 |
|---|---|
| 指标名 / 方法名与版本 | 如 `gjb_vn` v1（`method` 字段写入 `result.json`） |
| 标准编号 / 版本 / 条款 | 如 GJB / GB / EMVA 1288 具体条款，或内部专项算法基线 |
| 输入帧组与条件 | 所需批次数（单温度 / 高低温双点 / 暗场等）、帧数下限、有效位 |
| 标准差与掩码口径 | 明确分母 `N`（`sample_std = 0`）或 `N - 1`（`sample_std = 1`），以及 ROI/坏元掩码规则 |
| 输出与单位 | 标量、分布图或掩码尺寸、物理单位（DN / mK / % 等） |
| 小数组手算基准 | 极小输入（如 `2×2×2`）的手算精确预期值 |
| 离线参考与容差 | 参考数据集/对照工具及最大允许误差（如 `<= 1e-8 DN`） |
| 失败状态码 | 越界、帧数不足、空指针、退化分母等对应的 `IRStatus` |

## 现有样板与 Iteration 2 算法卡片

### 现有样板：矩形 ROI 均值

`IR_ROIMeanU16` 在仓库的 `analysis/roi_mean.cpp` 中实现。它对帧组中指定矩形内的所有像元求均值，输入为紧密排列的 `[帧][行][列] uint16_t`，输出为 DN。源码的 `sdk_tests/roi_mean.c` 随包安装到 `examples/roi_mean.c`，会检查左列 `41 DN`、整图 `51 DN` 和 ROI 越界。包内的 `roi_2x2.json` 工位和 `noise_roi_2x2.json` 配方可以用 CLI 复算。

### Noise3D（DN 两阶段：`analysis/noise3d_dn.cpp`）

| 字段 | 规格说明 |
|---|---|
| 入口函数 | `IR_Noise3DBuildCalibDn`、`IR_Noise3DComputeFramesDn` |
| 输入与条件 | `BuildCalib`：`mean_high_map`/`mean_low_map`/`rms_map`/`b_map`（全部有限，像元 `<= 10^7`）；`ComputeFrames`：`org_frames` `[帧][行][列] uint16_t`（`frame_count >= 2`，总样本 `<= 10^9`）、`total_blind_mask`、可选 `k_map`/`b_map`（`NUC` 模式必填） |
| 标准差与掩码 | 分量标准差采用**样本标准差（分母 `N - 1`）**；`*_blind_mask` 中 `1=盲元、0=非盲元`，`valid_mask` 中 `1=有效、0=盲元`；要求至少 2 个有效像元且每行每列至少 1 个有效像元 |
| 输出与单位 | `scalars[16]`（`DELTA_T..COLS`，单位 DN/计数）、`hist[4×hist_interval]`、`hist_meta[4×3]`、`map_ij`/`map_ti`/`map_tj`、可选 `nuc_frames` 与 `meta[32]` |
| 参考与容差 | 对应 `optmeas-usb/processing/noise3d_dn.cpp`；小数组手算及 `ORG`/`NUC` 回归（`sdk_tests/noise3d_test.cpp`）容差 `<= 1e-12` |
| 失败状态码 | 空指针 `IR_NULL_POINTER`、容量不足 `IR_BUFFER_TOO_SMALL`、参数非法/非有限输入 `IR_BAD_ARGUMENT`、有效像元不足/空行空列 `IR_COMPUTATION_FAILED` |

### GB / GJB 指标（`analysis/gb_gjb.cpp` + `analysis/matrix_view.h`）

| 字段 | 规格说明 |
|---|---|
| 入口函数 | `IR_GbProcessBadPixels`、`IR_GbEvaluateMaps`、`IR_GjbProcessBadPixels`、`IR_GjbEvaluateMaps` |
| 输入与条件 | 双黑体温度均值图 `v1_map`/`v2_map`、噪声图 `vn_map`（DN）、GJB 两点校正验证图 `vm_map`（DN）及辐射参数 `IRCalcParameters`（温度采用 `+273 K` 转换） |
| 标准差与掩码 | 上游逐像元噪声图 `vn_map` 须由 `IR_FrameStatisticsU16(..., sample_std = 0)`（**总体标准差，分母 `N`**）计算；内部 `maskedFiniteStdDev` 亦用分母 `validCount`；除零遵循 `safeDivide`（分母精确 `0.0` 返回 `0.0`）；`valid_mask` 中 `1=有效、0=盲元`，其余 `*_bad_mask` 中 `1=盲元、0=非盲元` |
| 输出与单位 | 去盲元前/后响应、SNR、NETD（mK）、NEP（W）、探测率、响应不均匀性（%）、SITF（DN/K）、GB 分区簇等级（`A..D`）、GJB 中心/边缘簇与 `3×3`/`4×4` 方块计数、空间噪声、最大动态范围（dB）与两点 NUC RFPN（V） |
| 参考与容差 | 对应 `optmeas-usb/processing/GjbDataProcess.cpp` 与 `tests/GbBadPixelTest.cpp`（`sdk_tests/gb_gjb_test.cpp` 全量 5 组盲元测试 + `1024×1280` + 闭式数值容差 `<= 1e-12`） |
| 失败状态码 | 空指针 `IR_NULL_POINTER`、输出/掩码容量不足 `IR_BUFFER_TOO_SMALL`、参数非法或除零 `IR_BAD_ARGUMENT`、全图无有限/有效像元 `IR_COMPUTATION_FAILED` |

### 可组合基础算子、1D FFT 与多 Burst 温漂指标（Stage A：`analysis/composable_ops.cpp` + `analysis/spectral_ops.cpp`）

| 字段 | 规格说明 |
|---|---|
| 入口函数 | `IR_BuildTwoPointNucF64`、`IR_ApplyAffineMapF64`、`IR_FrameStatisticsNucU16`、`IR_MapSummaryF64`、`IR_SpatialLowHighPassF64`、`IR_MapBinaryOpF64`、`IR_ThresholdMaskF64`、`IR_MaskCombine`、`IR_ComputeRfft1D`、`IR_ChannelSpectrumU16`、`IR_GjbEvaluateBurstMetrics` |
| 输入与条件 | `IR_FrameStatisticsNucU16` 按单遍 Welford 计算 `k*raw + b - dark` 均值与总体/样本噪声；`IR_SpatialLowHighPassF64` 为掩码感知二维盒式低通（去均值防大直流精度损失，支持 `15×15` LRNU/HRNU）；`IR_ComputeRfft1D` / `IR_ChannelSpectrumU16` 使用纯 C++ Radix-2 + Bluestein 支持任意 `length >= 2` |
| 标准差与掩码 | `IR_GjbEvaluateBurstMetrics` 通过 `IRGjbDriftContext` 参数化噪声正交扣减（`IR_NOISE_SUBTRACT_VARIANCE_QUADRATURE`）与 `lrnu_kernel_size`；盲元/有效掩码保持 `1=有效/通过、0=排除` 显式参数传递 |
| 参考与容差 | `sdk_tests/composable_ops_test.cpp` 与 `sdk_tests/drift_nodisk_test.cpp` 验证非 2 的幂长度（素数 `13`）FFT 精度 `<= 1e-9`、正交扣噪与 3-Burst 无存盘流程（`IR_FlushFrames` + `IR_FrameStatisticsNucU16`） |
| 失败状态码 | 偶数核尺寸、越界 ROI、非法掩码或 `length < 2` 返回 `IR_BAD_ARGUMENT`；零有效像元或退化两点差返回 `IR_COMPUTATION_FAILED` |

## 新增一个算法的步骤

1. 明确算法输入：帧数和几何、有效位、曝光/温度等条件、ROI 或掩码，以及算法要求的帧组。标准方法还要记录标准编号、版本和条款，不从产品描述推测标准口径。
2. 在 `analysis/` 实现纯计算函数；需要应用调用时，在 `include/IR_analysis.h` 增加 C ABI。用固定宽度类型、调用方缓冲区和显式容量，不暴露 C++ 类、Qt 或第三方容器。
3. 在 `sdk_tests/` 增加极小已知数据样例，给出预期值、单位、容差和无效输入；有现存 RAW 时再做离线复算。浮点容差按算法说明，不要求不同编译器逐位一致。
4. 如果配方需要调用算法，在 `station/procedures/recipe_metrics.cpp` 仿照 `prepareRoiMean` 写一个入口。它读取 JSON 参数，返回画幅检查和计算函数。把方法名、输出后缀、单位、方法名及版本登记到 `methods` 表。计算函数拿到同一个只读 `FrameBatch`，按声明顺序返回指标值。无配方调用需求的算法只需在 Analysis 提供入口和样例。
5. 更新开发指南、支持矩阵和 C/C#/Python 的调用说明。新方法必须可从安装包头文件编译调用；在 Windows 迭代分支上先通过 `tools/verify_windows.ps1` 验证，跨平台合包发布前再于 Linux 复验并核对跨平台数值容差。

```text
原始 RAW16 帧组
   ↓
IR_station：按配方取数、锁定设备、交付同一只读批次
   ↓
IR_analysis：基础运算 / 标准方法 → 数值、单位和方法版本
   ↓
流程结果：归档原始帧、条件、指标和限值状态
```

当前 `IR_analysis` 已交付基础统计（`temporal_noise` / `IR_ROIMeanU16`）、3D 噪声（`IR_Noise3D*`）与 GB/GJB 核心评价（`IR_Gb*`、`IR_Gjb*`）。JSON 自动配方流程当前直接支持 `temporal_noise` 与 `roi_mean`；多温点/多条件配方步、EMVA 1288 等其余标准方法将在确认编排与实测数据后逐步接入。

## 资源与并行约定

进程同时运行一条配方。多个指标和归档顺序共享同一份只读像素，手动预览与配方互斥。独立的离线 Analysis 调用可以由应用并行发起，各调用使用独立输出缓冲区。并行计算或写盘的安排由后续吞吐测量决定。
